# Contributing and requesting changes

`dxconvey` reads DX7II SysEx dumps and writes DX7 voices for the DX7, with a register of what
a conversion cannot carry. Corrections of the format claims, ideas, test files and — once the
source is out — code are welcome. Search existing issues and discussions before opening a new
topic.

The repository holds no code yet: the source lands with the first public release, planned for
December 2026. Until then the useful contributions are the ones that need no code at all; they
are listed under [What is useful now](#what-is-useful-now).

## Choose the right place

| Situation | Where to post |
| --- | --- |
| A sentence, a table or a figure of the README that the manual or the instrument contradicts | A **bug issue** |
| The tool does not do what the README says it does | A **bug issue** |
| An idea, a workflow need or a design question that still needs exploring | A discussion in **Ideas** |
| A feature or change request with defined behaviour and completion criteria | An **enhancement issue** |

Discussions help us decide what to build; issues track defined work. A precise request can go
straight to an issue: a discussion is not mandatory. A request that still needs design work may
be redirected to Ideas. An issue should link to the discussion that holds the reasoning, if
there is one.

- Issues: https://github.com/solyarisoftware/dxconvey/issues
- Ideas: https://github.com/solyarisoftware/dxconvey/discussions/categories/ideas
- Q&A: https://github.com/solyarisoftware/dxconvey/discussions/categories/q-a

## Identify the subject

Start the title with the surface the topic touches — `show`, `convert`, `instrument`, `docs` —
for example `show - a cartridge reports 32 voices and the summary says 31`. The maintainer
applies the labels: `area:*` for the surface, `machine:*` for the instrument, `target:*` for a
conversion target, beside `bug`, `enhancement` and `documentation`. Contributors are not
expected to have permission to manage labels.

**Say which machine.** A DX7II setting that a DX7 does not have is not a bug in the DX7 path,
and a report that does not say which instrument it is about cannot be triaged. Use the tag the
documents use — `[DX7II only]`, `[both]`, `[DX7 only]` — and name the TX802 when the question
is about the rack version.

## Report a bug

Include:

- the surface, the version from `dxconvey --version`, the operating system, and — before the
  first release — the section of the README that carries the claim in question;
- the input file **described, not attached**: kind (All-Data, bank, single voice), machine,
  size in bytes, and the header when it matters;
- what you ran, what you expected, what happened, and the exit code;
- the report itself, copied out of the terminal, once there is a tool to produce one.

**Do not attach a `.syx`.** It is the one thing this repository does not accept, and an
attachment is as public as a commit. A dump written by `examples/make_example.py` is the only
exception, because it can be regenerated byte for byte and its names belong to nobody.

A screenshot helps, but it does not replace the text: the text can be searched, quoted and
compared.

## Propose an idea or a defined change

For an **idea**, explain the music, the workflow and the problem, and why solving it would
help. Alternatives, examples and a description of the files involved are welcome; a design is
not required.

For a **defined change request**, describe the requested behaviour, its motivation, its scope,
and the observable result that would show it is done. Mention what it changes for the DX7 path
and for the DX7II path separately. An open discussion or issue does not guarantee acceptance,
implementation, priority or a delivery date: scope and priorities remain the maintainer's
decision.

## What is useful now

- **A contradiction, with its page.** The claim, the manual and the page number, or the
  measurement on the instrument. This is the contribution the project needs most: the
  documents of this repository are made of claims about two machines, and a wrong one is
  invisible until someone plays it.
- **A shape that breaks the reader.** The dump kind, the size, the header, and which field the
  tool reads in the wrong place — described, not attached.
- **Listening and comparison.** Once the first release is out, a converted voice played on a
  real DX7 and on the DX7II it came from.
- **Documentation.** A sentence that a musician had to read twice, and the version they would
  have written.

## Documentation conventions

- **`README.md` is the product page.** What the tool does, what it prints, what it refuses to
  do. The memory layouts, the byte offsets and the reasoning behind a rule belong in the
  commit that introduced them or in the issue that argued them, not on the front page.
- **The roadmap lives in issues and discussions, not in a file.** A `TODO.md` next to the code
  duplicates that, and then drifts out of date; it is not kept.
- **A figure is the output of a command, never a drawing.** Every figure of the documents is
  produced by the tool and compared with it, so the drawing and the arithmetic cannot
  disagree. When a figure is wrong, the command is wrong.
- **The language of the repository is English** — documents, code, comments, tests, `--help`,
  error messages, commit messages. The names of the instrument stay the ones Yamaha prints:
  `voice`, `performance`, `operator`, `feedback`, `envelope`, `bank`, `cartridge`.

## Optional support

If this tool is useful to you, you can optionally support its maintenance and development
through the donation link in the repository README:
https://github.com/solyarisoftware/dxconvey#supporting-the-work

Contributions help cover the time and costs involved in investigating requests, implementing
changes, testing and documentation.

Donations are entirely voluntary. You do not need to donate to report a bug, suggest an
improvement or contribute to a discussion. A donation does not guarantee implementation,
priority, a delivery date or support in exchange. It is not a purchase and does not change the
software licence or unlock features. Buying the DX7II banks is a separate thing: those are
sound files sold on the collection page, not funding for this software.
